# SHARP Calculator(EL-W506 / W516 / W546 模拟器)键盘支持

给 2008 年的夏普计算器模拟器加上电脑键盘输入,并在键帽右下角标出对应的键名。**不修改 EXE**,通过代理 `ice.dll` 实现。

> ⚠ 已在 Wine 中用模拟程序测试过按键映射逻辑。任何异常,把 `ice_core.dll` 改回 `ice.dll` 即可还原。

## 1. 安装(3 步)

1. 备份模拟器目录(`SHARP Calculator.exe` 所在目录)。
2. 把目录里原来的 `ice.dll` **改名为 `ice_core.dll`**(本包 `dist/ice_core.dll` 就是原文件的副本)。
3. 把本包的 `dist/ice.dll` 复制进去。可选:同时复制 `dist/keymap.ini` 自定义按键和角标。

目录结构应为:
```
EL_W506_W516_W546_v110\
  SHARP Calculator.exe
  ice.dll          <- 新的代理 DLL(本包)
  ice_core.dll     <- 原来的 ice.dll
  EL_W506.sim
  keymap.ini       <- 可选
  skin\  image\
```
还原:删除新 `ice.dll`,把 `ice_core.dll` 改回 `ice.dll`。

## 3. 2ndF / ALPHA / MODE 等二次键、多用键

模拟器里这些都是**普通按键**:EXE 只把"哪个键按下/抬起"告诉仿真核心,"2ndF 之后再按某键 = 第二功能"完全由计算器固件(`.sim`)处理,LCD 上的 2ndF/ALPHA 指示符也由固件驱动。因此键盘上**依次按下**即可,不需要同时按:

| 目标功能 | 键盘操作 |
|---|---|
| 第二功能(面板橙色字,如 `sin⁻¹`) | `F`(2ndF),再按 `S` |
| ALPHA 功能(字母/变量) | `A`,再按对应键 |
| 关机 OFF | `F`(2ndF),再按 `Esc`(ON/C) |
| SETUP | `F`(2ndF),再按 `U`(MATH) |
| 清除全部 CA / 删除 DEL | `F` 再 `F1`(MODE) / `F` 再 `Backspace` |
| F1–F4(公式存储,绿字) | `A`(ALPHA)再按 `↑` `←` `→` `↓` |
| 进入模式菜单 | `F1`(MODE),再用方向键/数字选择 |

面板上印在按键旁的其它小标签(hex、bin、dec、oct、deg、not、and、or、xor 等)在窗口里是**贴图标签控件**,不是独立按键;它们的触发方式同样是"2ndF/ALPHA/MODE + 某主键",以官方手册为准。

## 4. 关于型号

结论:**这套模拟器对应 EL-W506 / EL-W516 / EL-W546 这一个系列,最贴近的是 EL-W506(ROM 文件名即 `EL_W506.sim`)。** 依据与不确定之处:

- 夏普有一本**合订的英文说明书**,标题就是 "EL-W506/W516/W546",说明三者共用同一套操作说明。
- 论坛实物对比:EL-W506T 与 EL-W516T 面板、640 个功能完全一致,仅型号名不同(W516 主要在北美,W506 主要在欧洲及其它地区)。
- 你目录名 `EL_W506_W516_W546_v110` 的写法与此吻合。EXE 的关于框写的是 "Version 1.1 / Copyright 2008",也对得上 v110。
- 你说它"功能最齐全":相对 EL-W531/W535 成立。资料显示 W516 为 4 行 WriteView、640 个功能、7 种模式;W535 为 4 行、422 个功能、3 种模式。因此 W531/W535 的皮肤是这套的子集用法,这一点和你的观察一致。
- **我没有从二进制里找到可靠的型号标识**(EXE/DLL 中没有 "W506" 字样;`.sim` 里偶然出现的字符串是混淆数据的巧合,不能当证据)。所以"W516 与 W546 的 ROM 是否逐字节相同"无法证明,只能说它们同一说明书、同一操作方式。
- 注意:市面上还有 **EL-546X / EL-546W 之类的 2 行 WriteView 机型**(336~556 个功能),与本系列不是同一个,别混淆。
- 截图中 x³ 是 RCL 键上方的红色标签,不是独立按键,所以键编号 21 在窗口里空缺是正常的(此前我猜测与其它型号共用皮肤,该猜测作废)。
- 关于 "W566":你推测是夏普的内部型号(通过阉割做产品分级),有可能,但我没有二进制或资料层面的证据,只能当作未验证的假设。
- 如果要精确确认,可以把 `ReadMe.TXT` 的内容发给我。

## 5. 键帽角标(按键提示)

每个键帽右下角会用**黄色小字(深色描边)**标出对应的电脑键名,例如 2ndF 键上标 `F`、ON/C 上标 `Esc`、BS 上标 `Bksp`、D1–D4 上标 `F5`–`F8`。数字、运算符、方向键因为显而易见,默认不标。

- 实现:不改 EXE、不动背景位图。代理 DLL 再挂一个窗口消息钩子,在主窗口画完某个按键(`WM_DRAWITEM`)之后,用同一个画布把提示画上去;字高按键帽高度的比例计算,因此在 100%/200% 等缩放下都能自适应。
- 提示文字由当前映射**自动反推**:改了 `keymap.ini`,提示自动跟着变(例如 `ESC = -1` 之后 ON/C 的提示会变成 `Del`)。
- 在 `keymap.ini` 的 `[Hints]` 段可调:`Show`(总开关)、`ShowAll`(连数字/运算符/方向键也标出)、`Scale`(字号比例)、`Color`/`Edge`(文字/描边颜色)、`Text<k>`(单键改文字,留空即隐藏)。详见 `dist/keymap.ini`。
- 效果参考:`preview_key_hints_示意.png`(按你的截图估位的示意)与 `test/wine_mock_角标实测.png`(Wine 中按真实窗口坐标搭的模拟程序的实际渲染)。
- ⚠ 角标同样**只在模拟程序上验证过**:真实 EXE 的键面是否通过 `WM_DRAWITEM` 在主窗口处理期间绘制,我是从反汇编(`0x402930` 处 `ODT_BUTTON` 的 DrawItem)推断的,需要你在真机上确认(见验收清单第 7 条)。若角标完全不出现,把 `Show=0` 即可关闭,按键映射不受影响。

## 6. 粘贴:Ctrl+V

把剪贴板里的数字"打"进计算器:**粘贴的瞬间被转换成一串按键**(与鼠标点击/键盘映射走同一条路径),不是直接改计算器内存,所以计算器的显示、2ndF 状态、输入缓冲都由固件自己维护。

- **只允许纯数字或小数**:数字 `0-9`,最多一个 `.`;两端的空格/换行会先去掉。含任何其它字符(字母、逗号、`1e5`、`1+2`、多行、全角数字、第二个小数点……)一律**拒绝:响一声,什么都不输入**。
- 默认最多 32 个字符(数字+小数点)。`keymap.ini` 的 `[Clipboard]` 里可改 `MaxLen`;`AllowNegative=1` 时允许开头一个 `-`(会先按 `(−)` 键),默认关闭。
- 每个字符约 160 ms(按住 80 ms + 间隔 80 ms),用定时器分步执行,**不会卡住界面**。粘贴进行中按 **Esc** 立即中止(正按着的键会先松开)。
- 粘贴不会自动清屏。如果上一次的结果还在屏幕上,计算器自己会把新数字当作新输入;需要的话先按 Esc/Delete(ON/C)。
- 如果真机上发现**丢数字或重复数字**,说明模拟器处理按键比 80 ms 慢,把 `HoldMs`/`GapMs` 调大(例如 120/120)。这是我在 Wine 的模拟程序上验证的节奏,真实模拟核心的扫描周期还没验证。
- 没有选中计算器主窗口(例如 About 框在前面)时 Ctrl+V 原样放行,不会误触发。

## 7. 复制到剪贴板:方案与进展(开发中)

**现状:尚未实现 Ctrl+C。** 当前版本只提供"采集工具",用来让真机把需要的数据记下来。

读出计算器里的数字,有三条路:

| 方案 | 做法 | 评价 |
|---|---|---|
| **A. 读模拟 RAM(推荐)** | `CIce::GetBankedRam` 能读 256 bank × 128 字节的内部 RAM,直接解码 ANS/显示缓冲里的数值 | 最准(拿到的是真实数值,不受分数/指数显示格式影响);需要知道**地址和编码** |
| B. 读 LCD 点阵 | `CIce::GetPageFromLCDRam` 取点阵,用字模识别数字 | 不需要 RAM 布局;但要采集字库,分数/指数/多行显示都得处理,误识别风险大 |
| C. OCR 截图 | — | 不推荐 |

选 A 的理由:这个模拟器本质上是在 PC 上跑计算器的**真实固件**(`.sim` 是原始 16 位字 ROM),固件把结果存在 RAM 里,读 RAM 就等于读"计算器自己认为的数值"。唯一的未知数是地址和编码,而这个**必须在真机数据上确定**:我这里没有真实的模拟核心可运行(缺 MFC42.DLL)。

**采集工具(已实现并在模拟程序上测试)**:
- `Ctrl+Alt+K`:确认后,自动在计算器上输入 12 组测试(ON/C、`1234567`、`=`、`0.5`、`9.87654`、`(−)5`、`1÷3`、`2×3`、`7654321+1` ……),每步之后记录 **LCD 点阵(ASCII 画)** 和 **RAM 相对上一步的变化**,并自动在 RAM 里搜索刚输入的数字(按 ASCII、逐字节数字、压缩 BCD 高位在前/低位在前等 6 种编码)。约 30 秒,期间别动计算器,Esc 可中止。
- `Ctrl+Alt+D`:随时手动追加一份当前状态快照(想让我看某个特定显示时用)。
- 结果写在 EXE 同目录的 **`ice_probe.txt`**(只含计算器内存和 LCD,没有你电脑上的任何其它信息,几十 KB)。

**下一步**:请你在真机上按一次 `Ctrl+Alt+K`,把 `ice_probe.txt` 发给我。据此我会:① 找出 ANS/显示结果在 RAM 里的位置和编码(模拟测试里命中的是"ASCII 输入缓冲"和"压缩 BCD 的 ANS",真机上要看实际);② 写解码器(符号、小数点位置、指数、有效位数);③ 实现 `Ctrl+C`,并加上"显示/ANS"取舍和校验(例如读不出时不覆盖剪贴板)。LCD 点阵快照也会保留,作为解码不了(例如分数显示)时的备用方案。

## 8. 自定义按键(keymap.ini)

放在 `ice.dll` 同目录,`[Keymap]` 段,格式 `PC按键 = k`,`-1` 表示禁用。示例:
```ini
[Keymap]
ESC = -1      ; Esc 恢复为关闭窗口
J   = 5       ; J -> )
F9  = 0       ; F9 -> MODE
```
PC 按键可写:单个字符(A–Z 0–9 + - * / ( ) = . , ^),或 ENTER BACK ESC DEL UP DOWN LEFT RIGHT TAB SPACE DECIMAL HOME END PGUP PGDN F1–F12,或别名 EQUALS PLUS MINUS STAR SLASH DOT COMMA CARET LPAREN RPAREN。

## 9. 验收清单(请在 Windows 上做)

1. 程序正常启动,LCD 正常显示。
2. 依次按 `1` `+` `2` `=` 得 3。
3. `F` 再 `S`:出现 sin⁻¹ 之类第二功能;LCD 上 2ndF 指示符出现又消失。
4. `A` 之后字母输入、`F1` MODE 菜单、方向键移动光标、Backspace 删除、Esc 清除。
5. 长按一个键不应连续输入;点 About 对话框时按键不应影响计算器。
6. 键盘触发时按键"按下"的视觉效果是否与鼠标一致(未验证)。
7. 键帽右下角出现黄色键名;位置、大小是否合适(字太小就调大 `Scale`);按下一个键再松开后角标仍然在;窗口最小化再还原、被其它窗口遮挡后再露出,角标仍然在。
8. 粘贴:剪贴板放 `12.5`,在计算器窗口按 Ctrl+V,屏幕应依次出现 1、2、.、5,没有丢位/重复;放 `12a`、`1,234`、`1e5` 则响一声且无输入;粘贴一长串数字时按 Esc 能中止。丢位就调大 `HoldMs`/`GapMs`。
9. 采集:按 Ctrl+Alt+K → 确认 → 等约 30 秒,弹出"采集完成";EXE 目录下出现 `ice_probe.txt`(几十 KB)。若里面 `GetPageFromLCDRam=00000000` 或 `GetBankedRam=00000000`,请告诉我。
